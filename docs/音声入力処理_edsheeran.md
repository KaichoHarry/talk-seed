# 音声認識モジュール設計書

## 1. 担当範囲

本モジュールは、会話参加者の発話音声を取得し、テキストデータへ変換する機能を担当する。

具体的には、以下の機能を提供する。

* マイクからの音声取得
* 音声データの前処理
* 音声認識処理
* テキストデータ生成
* 後続モジュールへのテキスト送信

本モジュールによって生成されたテキストは、会話支援AIモジュールへ送信され、会話内容の理解や応答生成に利用される。

---

## 2. システム構成

本モジュールは、システム全体における入力処理部分として機能する。

会話参加者の発話を取得し、音声認識によってテキストへ変換した後、会話支援AIモジュールへ送信する。

当初はマイクを常時監視し無音区間を検出して自動的に発話区切りを判定する方式（PyAudio + VADによるローカル常時録音）を想定していたが、プロトタイプ開発では、ユーザーがマイクボタンを押して発話し、もう一度押して区切る「プッシュトゥトーク」方式を採用した。常時録音方式は誤検出や待ち時間の体感悪化のリスクがあり、開発期間内での安定動作を優先したための変更である。

```text
┌─────────────┐
│  会話参加者  │
└──────┬──────┘
       │ マイクボタンを押して発話
       ▼
┌──────────────────────┐
│ ブラウザ録音 (MediaRecorder) │
└──────┬───────────────┘
       │ マイクボタンを再度押して停止
       ▼
┌─────────────────────┐
│ サーバーへ音声ファイル送信 │
└──────┬──────────────┘
       ▼
┌─────────────┐
│ 音声認識(Whisper) │
└──────┬──────┘
       ▼
┌─────────────┐
│ テキスト生成 │
└──────┬──────┘
       ▼
┌─────────────┐
│ AIモジュール │
└─────────────┘
```

## 3. 機能要件

### 3-1. 音声取得機能

#### 概要

会話参加者がマイクボタンを押している間の発話音声を、ブラウザの`MediaRecorder` APIで取得する。

#### 入力

* 会話参加者の音声

#### 出力

* 録音済み音声ファイル(webm)

#### 処理内容

1. マイクボタン押下時に`navigator.mediaDevices.getUserMedia`でマイクへのアクセス許可を得る
2. `MediaRecorder`で録音を開始する
3. マイクボタン再押下で録音を停止し、音声ファイルをサーバーへ送信する

---

### 3-2. 音声認識機能

#### 概要

取得した音声ファイルをテキストへ変換する。

音声認識エンジンには Whisper (`openai-whisper`, baseモデル) を採用し、サーバーサイド(`POST /voice/transcribe`)で実行する。

#### 入力

* 音声ファイル(multipart/form-data)

#### 出力

* 認識結果テキスト

---

### 3-3. 発話区切りの判定（プッシュトゥトーク）

#### 概要

常時録音・無音区間の自動検出は行わず、ユーザーがマイクボタンを押している間だけを1発話として録音する。これにより発話区切りの誤検出を避け、応答生成までの待ち時間を利用者が把握しやすくしている。

#### 要件

* マイクボタンを離してから2秒以内に認識結果を返す
* 録音中・認識中・応答生成中の状態をUI上で明示する

---

### 3-4. テキスト送信機能

#### 概要

認識結果を後続のAIモジュール(`POST /conversation/respond`)へ送信する。

#### 出力形式（`POST /voice/transcribe`のレスポンス）

```json
{
  "text": "最近どこか旅行行った？"
}
```

---

## 4. 非機能要件

### 4-1. 応答速度

マイクボタンを離してから認識結果出力までの時間を2秒以内とする（実測値: 約1.3秒、開発環境・baseモデル）。

### 4-2. 認識精度

静かな環境において **90%以上の認識精度** を目標とする。

### 4-3. 可用性

30分以上の連続利用において安定して動作すること。

### 4-4. 対応言語

初期バージョンでは日本語のみを対象とする。

---

## 5. 使用技術

| 項目    | 採用技術    |
| ----- | ------- |
| 開発言語  | Python (サーバー) / TypeScript (クライアント) |
| 音声入力  | ブラウザ MediaRecorder API |
| 音声認識  | Whisper (openai-whisper, baseモデル, サーバーサイド) |
| データ形式 | JSON / multipart(音声ファイル) |

---

## 6. 処理フロー

```text
開始
 ↓
マイクボタン押下 → ブラウザで録音開始 (MediaRecorder)
 ↓
マイクボタン再押下 → 録音停止
 ↓
音声ファイルをサーバーへ送信 (POST /voice/transcribe)
 ↓
Whisperで音声認識
 ↓
テキストをレスポンスとして返却
 ↓
AIモジュールへ送信 (POST /conversation/respond)
 ↓
終了
```
